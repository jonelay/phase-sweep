# Staleness and attachment rules

Portable specification for result-store staleness and attachment logic.
These rules govern which stored results serve for a given motor and model
version. Reference implementation: the pure predicates in `sweepstore`
(`version_current`, `record_is_current`, `attached`), which phasesweep's
`ResultStore` and a downstream consumer's wrap; phasesweep ships a vendored copy as
`phasesweep._sweepstore`. Portable test vectors ship with it
(`load_vectors()`).

## 1. Version staleness

A stored result carries a model-code version stamp, written unconditionally
at save time. A result serves only when its stamp equals the live model
version for that model key.

**Missing stamp is stale.** A record with no version stamp is treated like a
stamp mismatch because the model version that produced it is unknown. The
model must run again rather than serve that record. Pre-stamp stores therefore
show empty histories and recompute on first access under a stamped registry.

**Computed-only.** The staleness check applies exclusively to records with
`source == "computed"`. Measured and published results are exempt: they
describe hardware, cannot be regenerated by a model re-run, and always
serve regardless of version stamp. All store, server, and validation read
paths must preserve this exemption; the test vectors define the shared
behavior without duplicating implementation expressions here.

A reimplementation that applies staleness uniformly will silently hide
measured data.

**Why identity hashing alone cannot do this job.** Run IDs are recomputed
at the *current* model version (`model_v=N` enters the hash when N > 1).
A superseded-physics record would therefore re-key to a fresh ID under the
new version and serve as a cache hit. The version stamp is the mechanism
that catches this — it sits outside the hash and is compared explicitly.

### Migration trap

The save path stamps any unstamped record with the current version. A
load-then-resave migration therefore marks legacy records as current
without re-running the physics. Migrations must set the version stamp
explicitly to the version that produced the result, or leave it absent to
force a re-run.

## 2. Attachment

A stored result attaches to a target motor by one of two identity
mechanisms, depending on its source.

**Computed results** attach by exact configuration identity: the record's
`motor_config_id` must equal the target's `motor_config_id`.
`motor_config_id` hashes motor-level inputs (geometry, materials, pole
pairs, populated optionals), excluding name and drive parameters;
model-specific drive parameters contribute to `run_id` through
`hash_fields`. A parameter edit changes the config ID and detaches all
prior computed results, which is correct: they were produced under
different inputs.

**Measured and published results** attach by stable hardware name: the
record's motor name must equal the target's motor name. A measurement
describes a physical motor, not a parameter set, so it follows the motor
through parameter edits. This is what makes the calibration workflow
possible — a user adjusts parameters and re-runs models while the
measurement stays attached for comparison.

Formally, a record R attaches to target T when:

```
R.motor_config_id == T.motor_config_id
OR (R.source != "computed" AND R.motor_name == T.motor_name)
```

Consequences:
- A save under a new config name that preserves `[motor] name` keeps
  measured attachments.
- A pure rename without parameter changes also keeps them — identical
  params produce the same config ID by the three-tier hashing design.

## 3. Upstream provenance

A record derived from another store's record links back to it through
`dataset_id` (which enters the run ID) and carries the upstream identity
under `metrics.upstream`: upstream model and version, run_id, motor
identity, and the upstream metrics consumed. Staleness of the upstream
record is not propagated automatically; the link is what makes it
checkable.

## 4. Single-source assumption

These rules assume one source per record. Where a record type assigns
source per channel rather than per record, apply each rule per channel: a
record may be partially stale (some channels serve, others do not). This
is a known extension point, not normatively specified here — phase-sweep's
store does not represent partial staleness.

## 5. Record shape

The dict shape of a stored phase-sweep row is declared in
`phasesweep.record_schema` (`MotorDict`, `RunConfigDict`, `RunResultDict`,
`StoredRecord`). `StoredRecord` is `RunResultDict` plus sweepstore's
envelope: `run_id` is stamped on save, but pre-envelope rows lack it, so
readers must key by `run_id` when present and recompute it from `config`
otherwise. `source` is a free string, not an enumeration — stores hold
provenance-qualified values such as `"published (ANSYS FEM)"`.

Run-time demands are optional `RunConfigDict` keys written only when
set: `slip`, `w_mech` (mechanical rad/s), `tau_ref` (N·m) and
`T_coolant` (°C). Each enters the run id only when present, so rows of
models that do not read it are unaffected. Compound motor blocks
(`thermal_network`, `flux_map`, `induction`) appear in `MotorDict` only
when the motor carries them, and adding one changes the motor's
`config_id` and therefore every run id for that motor.

A model's `produces` set is its metric contract: within a model version
it may only grow, and renaming a key or changing its unit is a version
bump. An `OK` row carries every key the set listed when the row was
written; a row written before a same-version addition may lack the new
key, so a consumer that requires it checks for presence or requires the
version that introduced it.

Real rows are pinned in `phasesweep/_vectors/record_vectors.json`
(`phasesweep.record_schema.load_record_vectors()`, regenerated by
`scripts/gen_record_vectors.py`). A consumer that reads phase-sweep rows
as dicts declares the keys it touches and checks them against these
shapes, for example as `MOTOR_FIELDS_READ` and `RECORD_FIELDS_READ`
constants. The reference predicates are `version_current`,
`record_is_current` and `attached` in `sweepstore`.
